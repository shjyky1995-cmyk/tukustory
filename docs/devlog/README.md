# 开发日志（devlog）约定

本目录记录项目的每一步开发节点，用于上下文管理、问题追溯与交接。

## 规则

1. 每个开发节点对应一条编号条目，格式见当日文件头部示例。
2. 每个节点完成后立即提交 Git，提交信息包含节点编号与摘要。
3. 条目必须包含：目标、变更内容、验证方式与结果、摘要、问题与追溯。
4. 发现问题的修复单独成条，注明“问题”“定位”“修复”“回归验证”，可追溯到引入该问题的节点。
5. 未验证的部分必须显式写明，不得用“完成”概括。
6. 当日文件命名：`YYYY-MM-DD.md`；跨天继续追加。

## 条目模板

```markdown
## NNN · 标题

- 节点：简短说明这一步做什么
- 提交：commit hash 或“未提交”
- 目标：本条要达成什么
- 变更：文件清单与要点
- 验证：命令与真实结果（构建／测试／人工检查）
- 摘要：一两句话的结果概述
- 问题与追溯：无 / 问题描述 → 定位 → 修复节点编号
```
